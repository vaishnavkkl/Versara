# Save flows, image transitions and header space

Save publishes the result through the native device saver and records the app
copy in Edited files and Recents. Results show the actual destination folder.
Successful results do not request a second Save to device action. Existing-file
and edit saves use Save / Save as new; Save as new keeps a distinct app copy as
well as its device copy. Image Apply still updates only the working copy, with
one final Save from the preview.

Image-to-PDF, page arrangement/extraction/deletion, merge/split, advanced PDF
outputs, image export/batch tools and privacy outputs publish during their
original save action. Generated bytes are kept for retry if device publication
fails. Partially saved batches mark completed files separately so retry does not
republish them. The existing serialized, recoverable native publication workflow
is reused. PDF results track the authoritative saved URI after replacement;
the deleted temporary output is not re-added to Recents.

PDF-to-image exposes All pages, Current page, a page-range field and JPG/PNG
directly above Save images. It saves the selected pages sequentially, up to 100,
using generated names, then shows their saved folder. There is no filename
dialog or separate device-save prompt for every page. One Save remaining images
action retries an interrupted batch. Its result list is virtualized rather than
mounting up to 100 cards at once.

Image-tool navigation releases the outgoing preview and yields two frames before
pushing the editor. Basic, advanced and text editors mount behind a lightweight
gate after the native transitionEnd event. Direct links/replacements have a
500 ms fallback, cancelled on teardown. The gate is keyed by tool/parameters so
tool replacement also waits. Heavy editors keep their existing lifetime and
draft handling after the gate opens.

The shared screen header reserves each action group's actual intrinsic width,
including nested help/history groups and orientation controls. The one-line title
takes the remaining width and truncates before overlapping controls. It no
longer assumes a multi-button child has the width of one button.

Validation: Expo lint, TypeScript and whitespace checks. No automated tests or
web builds were requested or run. No native dependency or native implementation
changed for this follow-up. Publication failures, cancellation, partial batches,
Save / Save as new, long titles, large text and release-device frame times still
need manual verification; static checks do not establish an FPS guarantee.
