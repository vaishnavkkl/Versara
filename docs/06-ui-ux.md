# UI, UX, and Feature Delivery

## UI & Visual Design
- **Visual Direction:** Clean, fast, utility-focused, modern, large tap targets, clear progress, excellent dark mode.
- Avoid cluttered "100 tools on one screen" dashboard looks.
- The user should understand the app within five seconds.
- Dashboard modules use quiet neutral surfaces, tinted category icons and consistent typography. Grid and list use the same shared card; only arrangement changes. PDF, Image, Edited files and Privacy form a balanced two-column catalog.
- PDF and Image open file-first category libraries, with recent files, small previews, search and one Open button. Each library shows only its own file type.
- Open a file to reach its full-screen preview. PDF pages appear in a single horizontal thumbnail strip below the canvas; tap a thumbnail to jump. Options includes vertical scrolling and focus view.
- Four quick actions and a Tools button stay visible after a file opens. Tools opens a spacious native sheet with search and the shared grid/list preference. Common PDF tools come first. Tools reuse the selected file. Unimplemented actions are disabled and collapsed under upcoming tools.
- Grid switches to a readable list on narrow windows or large accessibility text. Titles can wrap; controls retain 48-point hit targets. The layout picker reflects when grid is unavailable.
- Bottom tabs have stable, equal-width targets and persistent labels. One selection pill moves on the UI thread with an interruptible, non-overshooting spring. Reduced motion changes selection immediately; screen navigation never waits for the indicator.
- The quick actions form a horizontal row in portrait; landscape uses a side rail to preserve preview height.
- Editor options use action-specific SF Symbols on iOS and Material Icons on Android through the shared editor icon map. Crop ratios, filters, brush styles, rotation, page selection and export actions have meaningful symbols; settings and adjustment icons are reserved for those controls. Context-dependent choices pass explicit icons, and unmapped labels never fall back to a settings icon. Preserve the existing theme colors, labels and touch targets.
- Editor controls belong at the bottom when they fit. PDF Style, Select, Brush/Area and Settings, and image Settings, use measured footer space and font-scaled label widths. Only when that row is crowded do tool controls move into the top toolbar. Page navigation, orientation and common view actions keep their established top positions. Controls render once; inert measurement views cannot receive touches or accessibility focus.
- PDF text editing follows the same measured placement for Add/Select text and PDF options. These controls remain accessible at the top while the keyboard hides the main footer. Image text formatting, adjustment panels and privacy cover controls stay in their bottom docks; common navigation and the image text confirmation checkmark retain their header positions.
- Edit text in images starts from the selected line's own style. Recognition estimates each line's size, baseline, start and weight from its pixels: the tight ink box is measured against the recognized text's glyph bounds, and the typical stem width decides bold. The family is chosen by shape: each candidate font (the three standard families plus the bundled fonts) draws the recognized text onto a small grid, and the one whose glyphs overlap the line's ink best wins (first 120 lines; later lines use the width match). The replacement is stretched horizontally to the original's letter width; picking a different font drops the stretch. On Android the lines come from ML Kit; on iOS from Vision. The line keeps its original pixels until the text, style, colour or position changes, so selecting text never restyles it. Applying an untouched line commits nothing.
- Edited-file rows, page selection/reordering, privacy findings and tool cards reuse memoized components and stable event callbacks. Edited files and PDF page lists decode thumbnails only for visible rows on the active screen; hidden thumbnail owners release native work. Replaced thumbnail files remain protected until their last viewer releases them.
- Custom dialogs use theme-specific input surfaces and translucent text selection colors so selected filenames and messages remain readable in dark mode.
- Toolbox sheets show their first options immediately in a bounded, virtualized three-column catalog. The native presenter owns a fixed 75%-height viewport; the React Native list is the only scroll owner. Header/search stay fixed, rows mount in small batches, cards use shared themed surfaces, and incomplete rows keep equal column widths. Short file-action catalogs omit search. There is no artificial loading delay or full-catalog content measurement. Content stays present during dismissal; image tool switching shows progress while applying the working copy.
- Edit text in PDFs and images offers bundled SIL OFL fonts (`assets/fonts/edit/`, catalogue in `src/constants/edit-fonts.ts`), grouped as Standard, Sans serif, Serif, Monospace, Display and Script. Each name previews in its own face. Bold and italic are disabled for fonts without those styles. Drafts store the font name; the font file path is added when sending to native code. PDFium embeds the TrueType file into the PDF, and the image renderers draw from the same file.
- Live image previews stay smooth: native code keeps one decoded preview source per file (up to 1280 px) and encodes opaque frames as JPEG. JS sends changes at most every 40 ms (curve drags every 60 ms). Sliders own their value while dragging (`src/hooks/use-slider-value.ts`) and only take outside changes such as undo or reset.
- Select & resize in the markup tools (PDF and image shapes, drawing, signatures) shows a dashed outline with small square handles on the corners and edge midpoints (corners only for images, which keep their proportions) and a round move handle in the middle. Boxes smaller than about 64 points show the move handle just below the box so the finger never hides the shape. The nearest handle under the finger wins, and grabbing a handle never makes the edge jump. While a shape is being moved, resized or drawn, a magnified view appears at the top right (top left when the finger is there) and disappears when the finger stops touching. Zoom in and Zoom out buttons float at the bottom right while selecting; they zoom around the selected mark and disable at 1x and 6x. Above them, Smaller and Larger (− and +) resize the selected mark by 20% around its centre, staying on the page; quick taps merge into one undo step. This is the reliable way to grow shapes too small to pinch or drag. With nothing selected, − and + act on the newest shape on the page, so a tiny shape can be enlarged right after drawing it.
- Protect PDF asks for the password in a bottom sheet that opens with the tool; the page preview keeps its full height. Protect PDF in the sheet creates the file, and an invalid password reopens the sheet with the reason.
- Sign PDF remembers the signatures in each saved PDF (up to six): an image as the version used, with or without its background, and the strokes drawn on a page as one drawn signature. The two most recent appear next to Add image; Recent lists all of them with a delete action. One tap places a signature in the middle of the page; a drawn signature undoes as one step.
- Reorder pages shows the pages in a three-column grid. Long-press a page and drag it: a lifted copy follows the finger, the drop position is outlined, the list scrolls near the top and bottom edges, and the page moves on release. Tap a page to preview it. Screen readers get Move earlier and Move later actions on each page.
- In select mode, a drag that starts away from every mark moves the page (when zoomed), and a sideways swipe at fit zoom changes page in PDF Add shape. PDF Add shape never draws from a touch: the page always selects, moves or scrolls, and Add shape in the bottom row places the picked shape in the middle of the page, already selected for moving and resizing.
- The PDF and Image libraries support pull to refresh: the native list (`RecentImagesView`, list version 4) uses `SwipeRefreshLayout` on Android and `UIRefreshControl` on iOS, and the React Native fallback list uses `RefreshControl`. Refreshing clears the list cache and rescans device PDFs.
- Every tool header shows icon-only Save and Share buttons on the right. Save runs the tool's main action (Save, Apply, Create or the processing action); after processing it saves the single result to the device. It is disabled when there is nothing to save or when several results each need their own card.
- Tone Curves docks only the channel chips, a compact graph and a one-line readout, leaving the rest of the screen to the preview. Drag a point on the graph to change it.
- Tone-curve SVG paths are calculated entirely inside one worklet using a loop. Avoid nested array callbacks that the React compiler can hoist into RN-runtime functions; inspect the compiled worklet when changing gesture calculations.
- PDF tools share Edit PDF's page navigation, full-height preview canvas and fixed action area. Numbering and source-page previews reuse its native zoom canvas. Text drafts update as native renders complete while typing; annotation controls remain outside the preview. See [consistent PDF previews](26-consistent-pdf-previews.md).
- Show the Versara logo immediately in the native launch splash in both appearances. Hide it after the first root layout and appearance restoration with a short native fade. Do not add an artificial hold or a second React introduction; startup recovery begins after the handoff.
- Tool screens share one header: back on the left, the tool name centred and Share on the right. Share sends the current edited file, rendered fresh when there are unsaved changes, otherwise the saved result or the original.
- Under the header, the tool action row keeps undo/redo on the left, page navigation centred and tool buttons (Style, Options, rotate) on the right. In landscape it becomes a left rail beside the preview, matching the PDF preview's side rails; tool actions stay in the right-hand column.
- Text style, colour, text lists and PDF options open as native bottom sheets over the preview, grouped into rounded cards. Font and size share one row; bold, italic and underline form their own group. Colour swatches wrap onto new lines instead of scrolling sideways.
- Scan Text (OCR) and Extract text keep their settings in a bottom sheet. After export, the full text opens in a Recognized text sheet, one page at a time, as selectable paragraphs. Wrapped lines are joined, hyphenated words are rejoined, and list items stay separate. It offers Copy all, Copy page, copy per paragraph and an Original lines view. Exports over 2 MB show the native preview and point to the saved file. Fit page is always the first button on the left of a tool's page or options row. A preview keeps a floating Fit button only on screens without such a row.
- In the PDF reader, the bottom bar's Tools button turns on the tools-around-page view, and the All tools button next to Fit page opens the full toolbox sheet. The bottom bar's four tools are the PDF tools used most recently (from tool history, which follows the search history setting), topped up with Edit PDF, Scan Text, Remove Text and Add Text. While the ring shows, the header close button and Android back first hide the ring; the next press closes the reader. The ring also starts with a Hide tools button.
- The tools-around-page view (formerly a button next to Fit page): It hides the bottom tool bar and thumbnails, fits the page into a slightly smaller rounded frame, and places every available tool as a colour-coded icon on all four sides. Sides share tools in proportion to their room and scroll if needed. A long press shows the tool name; screen readers announce it. The header ? button switches to name mode while the ring shows: icons get a dashed blue outline, and a tap shows the tool name as a toast instead of opening it. Tapping ? again, or pressing close or back, leaves name mode.
- The image preview follows the same layout (`src/features/files/image-viewer.tsx`, ring state in `src/hooks/use-tool-ring.ts`):
  - A row above the image has Fit image, which returns to the fitted size, and All tools, which opens the toolbox sheet.
  - The bottom bar shows the four most recently used image tools, filled with Edit text, Add text, Crop and Filters.
  - Its Tools button frames the image with every available image tool.
  - Close/back, long press and ? name mode behave as in the PDF reader.
  - Videos keep their own tool bar.
- Image edits are applied in tools and saved once from the preview:
  - Edit tools (crop, rotate, adjust, filters, resize, text, drawing, watermark, blur, colour and similar) show Apply instead of Save. Apply writes losslessly into the image's working copy (`image-workspace.tsx`) and returns to that image's preview. Closing a tool drops only its unapplied changes.
  - When changes are pending, the preview shows the working copy with Save and Discard all changes. Save asks Save / Save as new and keeps the original's format (JPEG, PNG or WebP). Create PDF, Share and Save use the working copy. Closing the preview with unsaved changes asks to save, discard or keep editing. The working copy survives app restarts.
  - Output tools make a file by design: batch, compress, convert, remove metadata, rename, and the editor's Export tab. Their save action publishes to the destination folder and shows its location; successful results do not ask to save again. Format and quality options appear only on these.
  - PDF-to-image shows All pages, Current page, page ranges and image format above Save images, then saves the selected images as one batch and reports the folder. Only failed/unfinished publications offer a retry.
- Shape pickers open as a 4 × 4 tile grid; long shape names shrink to fit their tile. The button toggles back to the normal layout. While the ring shows, the reader scrolls vertically and every visible page stays clear, including short image-to-PDF pages. Tools use the reader's current page; the page controls can select it explicitly when several short pages fit. A labelled Hide tools button and Back dismiss the ring. Its four groups animate on the UI thread; the native page surface stays static.
- Page Numbers and Watermark keep the preview full size. Their full settings open from Settings in a bottom sheet. Basic choices stay in a slim row above Save: number format and text size for Page Numbers; label text and strength (Subtle, Balanced, Bold) for Watermark. The preview refreshes automatically as settings change.
- Image tools follow the PDF tool layout. The advanced image tools keep Fit page first in the top row; the preview row holds Compare, Draw's icon-only Brush, Shape and Stroke eraser, and a Style and colour (or Image options) button that opens a bottom sheet. Exposure, Tone Curves, Levels, HSL, Sharpen, Blur and Canvas have no sheet: their controls dock under the preview so the live result stays visible. They show one slider at a time, and chips choose what it controls (black point, midtones or white point; hue, saturation or lightness for the chosen colour). Tone Curves is edited directly on its graph. The Image editor keeps crop, rotate, filter and Adjust controls inline above its tabs. Adjust shows one slider, with Brightness, Contrast, Saturation and Warmth chips and Reset all; opening Contrast, Saturation or Temperature from the toolbox selects that slider. Resize and Export open in a bottom sheet; Compare sits in the top row. Its editor view always shows the whole image, so it has no Fit button. Sheets for live edits (style, adjustments, page numbers, watermark) do not dim the preview.
- Every bottom sheet uses `@gorhom/bottom-sheet` through the shared `AppBottomSheet` (`src/components/app-bottom-sheet.tsx`): tool option sheets, the Recognized text sheet, menu and grid pickers, and toolboxes. Sheets size to their content up to a cap (about 70% of the screen, 92% for long content and landscape), scroll inside, and close by swipe, backdrop tap, the close button or Android back. The title row sits in the sheet handle so content height is measured correctly. The keyboard and a sheet never compete for the screen. Opening a sheet dismisses the keyboard. If the keyboard opens for a field outside the sheet, the sheet closes. Fields inside a sheet, such as toolbox search or a size box, keep it open. Do not add native `@expo/ui` or React Native `Modal` sheets.
- Brush, stroke and Settings menus in Draw tools open as tile grids. PDF Draw and Highlight use icon-only buttons so every control fits in one row: Brush (grid, includes Area highlight), Shape, Style and colour (colour, thickness, opacity, line style, keep-editable on save), Stroke eraser, and Page annotations. Edit PDF's text bar has smaller/larger buttons for the text size.
- Edit PDF, Add Text and Remove Text have Search in their page row. It finds text on every page natively and lists the matches; tapping one goes to its page and opens that text for editing (or selects it for deletion).
- Find & Replace is its own PDF tool, also opened from Replace in the reader's search bar with the search text filled in. Replace all turns the matches into ordinary text edits (one undo step, original font kept where possible). Matches split across text pieces, scans and protected text are skipped. In landscape, Add text, Text list and Save stack in a narrow column on the right.
- Save buttons use the floppy-disk icon on Android. SF Symbols has no floppy disk, so iOS keeps its standard save symbol.
- The PDF preview uses Edit PDF's page row: page navigation centred, search and rotate on the right. In landscape both screens share one layout. The page row is a left rail, page thumbnails sit in side columns (odd pages left, even pages right) and the page keeps its full height. On the standalone preview, the landscape/portrait switch sits next to the close button. Tools opened from the preview start on the same page and in the same orientation.
- On Android, Versara appears in the system "Open with" chooser for PDFs and images. The file is copied into the library, then opens in the PDF reader or image preview, with Home beneath it.
- Recents use local SQLite metadata and durable imported copies. Removing an import preserves the external original. Newly created PDFs appear in PDF Recents.

## Tool Registry & Search
- Implement a local tool registry to avoid hardcoded navigation. 
- Implement local search mapping terms to capabilities (e.g., "join pdf" -> Merge PDF).
- Every utility ends with a consistent result screen (Open, Share, Save to Files, Run Again, Delete Output).

## Feature Delivery (Definition of Done)
A feature is complete only when:
1. UI exists.
2. Native implementation exists.
3. iOS and Android implementations work.
4. Offline behavior works where promised.
5. Permission behavior is correct (asked just-in-time, no broad startup permissions).
6. Large files tested.
7. Errors handled.
8. Cancellation works.
9. Temp files cleaned up.
10. Output saved/shared.
11. Manual device validation is documented; no automated tests or web builds per project preference.
12. Accessibility labels and Dark mode work.
13. No unnecessary network requests.
14. AI is not required for deterministic functionality.

## Search/ASO Architecture
Store metadata should target real user intents (PDF editor, page numbering, photo compressor) rather than keyword stuffing the brand name. Balance popular competitive terms against specific ones.
